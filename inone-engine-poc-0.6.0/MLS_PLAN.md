# Групповое шифрование на MLS: план и результаты эксперимента

Дата: 2026-10-25. Решение владельца: MLS для групп и личных чатов, Megolm отменён. Срок увеличен ради надёжности в боевом режиме.

## Что проверено

Библиотека: `ts-mls` 1.6.4 (MIT), реализация RFC 9420 на TypeScript. Набор шифров: `MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519`.

Сценарий (`spike.mjs`):
- группа из трёх участников: создание, добавление двух через приветственное сообщение (Welcome); все читают одно сообщение;
- удаление участника коммитом; оставшийся участник читает новые сообщения; удалённый не читает (ошибка OperationError).

Результат: сценарий проходит.

Проверка чувствительности (`break.mjs`): если вместо удаления сделать пустой коммит, удалённый участник продолжает читать. Значит, проверка ловит ошибку, а не проходит впустую.

## Замеры стоимости (`bench.mjs`, Node, один поток)

| Участников | Среднее добавление | Удаление одного участника | Сообщение об удалении |
|---|---|---|---|
| 100 | 24 мс | 111 мс | 8,7 КБ |
| 500 | 96 мс | 653 мс | 41,6 КБ |

Замер сделан на дереве, построенном только добавлениями: это худший случай, потому что в нём много непрорастворённых листьев. Установившийся режим с обновлениями ключей измерим на следующем этапе. На телефонах замеров пока нет.

Для сравнения: Megolm при выходе участника требует около n² отправок, то есть около 250 тысяч для 500 участников.

## Риски

1. **Аудита `ts-mls` нет.** В README прямо сказано, что формальный аудит не проводился. Нужен внешний аудит нашей интеграции и решение по библиотеке.
2. **Неполные зависимости.** В `ts-mls` 1.6.4 код импортирует `@noble/hashes`, который не объявлен в её зависимостях. Версии зависимостей закрепляем, это пункт аудита.
3. **Мобильная библиотека не выбрана.** Основной кандидат — OpenMLS (Rust), подключаемый через FFI к iOS и Android. Аудит OpenMLS в найденных источниках не подтверждён. Dart-обёртка `openmls_dart` имеет низкую оценку зрелости в каталоге пакетов (0 из 15 по зрелости), на неё опираться нельзя.
4. **Не измерено** на телефонах: время обработки коммита и размер сообщений в установившейся группе на 500 участников.

## Этапы

1. **Контракт сервера (служба доставки).** Загрузка и выдача KeyPackage; приём коммитов с проверкой эпохи, чтобы конфликтующие коммиты отклонялись и не возникало развилок; доставка приветственных сообщений через уже существующую доставку «устройство — устройство»; хранение зашифрованных сообщений группы. Тесты в памяти и на PostgreSQL, проверка сломанным кодом.
2. **Эталонный клиент в движке (ts-mls).** Создание группы, добавление, удаление с проверкой, что удалённый не читает; конфликт коммитов; повторная доставка; сообщения не по порядку.
3. **Мобильный путь.** Сборка OpenMLS для iOS и Android, вызов из Flutter, замеры на устройстве. Решение по библиотеке.
4. **Безопасность.** Внешний аудит интеграции и библиотеки; закрепление зависимостей; приватные ключи MLS в Keychain (iOS) и Keystore (Android).
5. **Установившийся режим.** Замеры для 500 участников с обновлениями ключей.
