# Файлы: загрузка и скачивание (пункт 9)

- **Дата:** 2026-10-30 19:34 UTC (Ереван UTC+4).
- **Принцип:** клиент шифрует файл до отправки. Сервер хранит и отдаёт только шифротекст и не знает содержимого.

## Путь файла
1. `POST /files` с `kind` (`avatar` | `image` | `video` | `file`), `size`, `sha256` (SHA-256 шифротекста) и `roomId` (кроме аватара). Ответ: `fileId`, `uploadUrl`, `method: PUT`, срок 15 минут.
2. `PUT uploadUrl` с байтами шифротекста. Сервер проверяет подпись, срок, размер, SHA-256 до сохранения.
3. `POST /files/:id/complete` — владелец подтверждает загрузку. Файл становится готовым.
4. Сообщение комнаты с полем `fileId`: прикрепляется только готовый файл владельца этой комнаты. В ленте остаётся ссылка `file`.
5. Получатель: `GET /files/:id/url` (только участник комнаты) — ссылка скачивания на 5 минут. По ней отдаются байты.

## Лимиты
- Размер: аватар 5 МБ, изображение 20 МБ, видео 100 МБ, файл 250 МБ.
- Незавершённых загрузок на пользователя: 20.
- Брошенные (не подтверждённые) загрузки старше суток удаляются вместе с байтами (`cleanupFiles`).

## Безопасность
- Подпись адреса (HMAC) связывает срок, размер и SHA-256. Подмена любого из них отвергается.
- Размер не больше заявленного, контрольная сумма совпадает — иначе байты не сохраняются (413 / 422).
- Загрузка в комнату и ссылка скачивания — только для участников с нужным правом.
- Прикрепить можно только готовый файл владельца из этой комнаты.
- Ответ со скачиванием: `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. Браузер не открывает файл как страницу.
- Байты файлов не пишутся в журнал. Ключ объекта — случайный идентификатор, имя файла на сервере не используется.

## Что сервер видит
Вид, размер, SHA-256 шифротекста, комнату, владельца и время. Содержимого файла сервер не видит.

## Не сделано
1. Объектное хранилище на диске или у облака: сейчас в памяти. Для выпуска нужна реализация того же интерфейса, включение в резервные копии (`BACKUP.md`, пункт 5).
2. Шифрование файла на клиенте — задача клиента.
3. Миниатюры и предпросмотр — при шифровании делаются на клиенте.
4. Сканирование содержимого на вредоносный код на сервере невозможно для шифротекста. Решение — на клиенте и по политике владельца.
5. Квоты по объёму на пользователя — не сделаны, решение владельца о тарифах.
6. CDN — не нужен на этом этапе.
