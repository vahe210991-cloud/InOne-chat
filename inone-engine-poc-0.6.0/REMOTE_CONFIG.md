# Удалённая конфигурация и флаги функций (пункты 11–12)

- **Дата:** 2026-10-31 21:41 UTC (Ереван UTC+4).
- **Принцип:** умолчания лежат в коде (`src/flags.js`). Сервер и приложение работают без связи с оператором. Оператор меняет значения командой; каждое изменение пишется в журнал с именем оператора и причиной.

## Как меняет оператор
```
DATABASE_URL=... INONE_PIN_PEPPER=... node scripts/set-flag.mjs set <ключ> <значение> --actor "<кто>" --reason "<почему, не короче 10 символов>"
DATABASE_URL=... INONE_PIN_PEPPER=... node scripts/set-flag.mjs list
DATABASE_URL=... INONE_PIN_PEPPER=... node scripts/set-flag.mjs history <ключ>
```
Сознательно нет HTTP-интерфейса для изменения флагов: менять может только тот, у кого есть доступ к базе и секреты сервера.

## Ключи
| Ключ | Умолчание | Значения | Что делает | Где проверяется |
|---|---|---|---|---|
| `files.enabled` | да | да / нет | загрузка файлов | выдача адреса загрузки, загрузка, прикрепление |
| `push.enabled` | да | да / нет | уведомления | регистрация токена, отправка |
| `messages.editWindowMinutes` | 15 | 1–1440 | окно правки | правка сообщения |
| `channels.enabled` | да | да / нет | создание каналов | создание комнаты с видом «канал» |
| `groups.maxMembers` | 500 | 2–500 | предел участников группы | фиксация состава, приглашение, вступление, добавление |
| `maintenance.enabled` | нет | да / нет | режим обслуживания | все записи и загрузки отключены; чтение, выход и обновление сессии работают |
| `app.minVersion` | 0.0.0 | x.y.z | минимальная версия приложения | публичная часть конфигурации |

## Что видит приложение
- `GET /config` (после входа): версия и значения. Есть ETag: повтор с `If-None-Match` без изменений даёт 304.
- `GET /config/public` (без входа): только `maintenance.enabled` и `app.minVersion`.

## Открыто
1. Предел группы. Сейчас проверка принимает значения от 2 до 500. Если продукт требует больше 500 участников, предел нужно поднять, и это решение владельца.
2. Каналы включены по умолчанию (как сейчас в коде). До этапа каналов в продакшене их, возможно, стоит выключить.
3. Клиентская часть `RemoteConfigService` (заглушка без связи, кэш последнего значения, вариант для разработки) — следующий шаг на клиенте.
4. Постепенное включение (по процентам или по пользователям) и расписание изменений — не сделано.
5. Доступность модулей по организациям — после появления организаций.
