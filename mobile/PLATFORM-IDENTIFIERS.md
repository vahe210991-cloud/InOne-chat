# Native platform identifiers

The canonical Beta 1.0 application identifiers are:

- Android application ID: `com.inone.app`
- iOS Bundle ID: `com.inone.app`

Both values are generated by the pinned Flutter platform bootstrap with:

```sh
flutter create --platforms=android,ios --project-name app --org com.inone --no-pub <temporary-app-directory>
```

The repository helper `tool/generate_flutter_platforms.sh` copies the generated `android/` and `ios/` projects into the mobile workspace. The Flutter mobile and iOS validation workflows use this helper before building. Do not change the project name or organization independently: doing so changes the generated package/bundle identifiers.

Android's Rust bootstrap writes `MainActivity.kt` under `android/app/src/main/kotlin/com/inone/app/` with package `com.inone.app`. iOS uses the generated `PRODUCT_BUNDLE_IDENTIFIER = com.inone.app` setting.

Firebase app registrations must use these exact identifiers. The Firebase configuration files are environment/project-specific and must be downloaded from the Firebase Console; never create placeholder `google-services.json` or `GoogleService-Info.plist` files.
