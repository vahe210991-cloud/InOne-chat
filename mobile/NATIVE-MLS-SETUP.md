# Native MLS setup and acceptance

## Scope

This branch ports the Stage 4 persistent OpenMLS client into the active native Flutter branch and adds the Rust-owned session boundary:

- Rust MlsSession owns the OpenMLS client and refresh-token rotation.
- SQLCipher stores persistent MLS state and the local inbox/outbox.
- PlatformKeyStore stores the 32-byte SQLCipher key in Android Keystore or protected iOS Keychain. The key is never returned to Dart.
- Flutter receives only a short-lived access-token snapshot.
- A saved user/device identity resumes the Rust session after app restart.
- After adoption/resume, the app publishes KeyPackages, processes pending Welcomes, syncs known rooms and flushes the Rust-owned text outbox.
- Logout attempts server logout and always removes local SQLCipher files/sidecars and the platform key.
- Native MLS is opt-in through INONE_MLS_NATIVE_ENABLED=true; the default remains disabled.

The Rust client now has an end-to-end attachment path: per-file AES-256-GCM, ciphertext-only upload, MLS-encrypted versioned manifest, SQLCipher persistence and authenticated download/decryption. The Rust integration test exercises two devices, restart persistence and idempotent retries. These changes are still uncompiled/unrun in this environment.

## Generate Flutter Rust Bridge files on Windows

Requirements:
- Flutter stable 3.47.x or newer
- Rust 1.91.0 or newer
- Cargo and Node.js
- Android SDK/NDK for Android builds
- macOS + Xcode are required for iOS builds and Protected Keychain runtime validation

From PowerShell:

```powershell
cd mobile
.\tool\generate_native_mls.ps1
```

The script pins flutter_rust_bridge_codegen to 2.13.0, creates Android/iOS platform projects, integrates the Native Assets backend, generates Dart/Rust bindings, prepares Android application-context initialization, resolves Dart dependencies, creates the Rust lockfile and formats the bridge crate.

Expected generated files include:
- mobile/hook/build.dart
- mobile/lib/src/rust/**
- mobile/rust/build.rs
- mobile/rust/src/frb_generated.rs
- mobile/rust/Cargo.lock

These generated files are intentionally not fabricated or hand-written. They must be generated by the pinned code generator and committed from the exact source revision.

## Validation gate

After generation, run:

```powershell
flutter analyze
flutter test
cargo test --locked --manifest-path rust/Cargo.toml
Push-Location ..\inone-development-archive-0.6.0\engine
npm ci
Pop-Location
$env:INONE_ENGINE_DIR = (Resolve-Path ..\inone-development-archive-0.6.0\engine).Path
cargo test --locked --manifest-path ..\inone-engine-poc-0.6.0\mobile-mls\mls-client\Cargo.toml -- --test-threads=1
flutter build apk --debug
```

Then run the Android Keystore integration test on an emulator/device. On macOS, build both iOS device and simulator targets and run the protected Keychain integration test with the signed app.

Do not set INONE_MLS_NATIVE_ENABLED=true for release until:
1. generated FRB files exist and are committed;
2. Rust bridge and persistent MLS client tests pass;
3. Flutter analyze/tests pass;
4. Android Keystore persistence/restart/revocation smoke tests pass;
5. iOS Protected Keychain persistence/restart smoke tests pass;
6. the same exact commit SHA passes all checks.
