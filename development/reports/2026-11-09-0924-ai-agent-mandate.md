## 1. Цель этапа

Владелец потребовал единый обязательный протокол, который каждый исполнитель InOne должен прочитать перед работой. Он закрепляет 14 правил: полное чтение; отчёт после каждого этапа; отсутствие локального долговременного хранения; commit/push последних версий; разбор каждого файла из чата; rolling checklist 5+5 с зачёркиванием; накопительная готовность; запрет подмены GitHub отчёта сообщением в чате; актуализация continuity/bundles; отсутствие придуманных решений; merge только после полностью зелёного CI; использование GitHub возможностей; сервер только с разрешения; commit/push каждого результата.

## 3. Важное ограничение памяти и навыков моделей

Файлы репозитория не могут технически заставить любую внешнюю модель автоматически сохранить текст во внутренней памяти/skills или гарантировать, что новый чат прочитает его. Это зависит от платформы и её настроек. Поэтому реализована доступная и проверяемая гарантия на уровне репозитория: корневой `AGENTS.md`, Copilot instructions, корневой README и development entrypoint указывают на полный mandate и требуют перечитать его в каждой сессии. Нельзя утверждать, что внутренняя память всех моделей изменена.
