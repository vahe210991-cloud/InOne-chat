# InOne — аудит и первые исправления движка

**Дата:** 2026-11-14  
**Ветка:** `feat/flutter-ui-dart-migration-2026-11-14`  
**Статус:** первичная стабилизация; production readiness НЕ подтверждена.

## 1. Задача

Разделить и зафиксировать два независимых компонента:

1. **Серверный движок:** HTTP API, аккаунты, сессии, устройства, организации, сообщения и PostgreSQL persistence.
2. **Криптографический движок клиента:** создание/хранение ключей, MLS state transitions, шифрование и расшифрование на устройстве.

Цель — один однозначный серверный источник кода, постоянное хранилище без скрытого in-memory fallback в production, утверждённый MLS-клиентский путь и проверяемые эксплуатационные гарантии. Не объявлять alpha-код production-safe до полного набора проверок и независимого аудита.

## 2. Подтверждённые проблемы

- Мобильные документы указывали на `inone-development-archive-0.6.0/engine/src/server.js`, тогда как актуальная рабочая реализация находится в `inone-engine-poc-0.6.0/src/server.js`. Это создавало риск проверки маршрутов не того дерева.
- `src/main.js` создаёт PostgreSQL pool и передаёт PostgreSQL store в API, но экспортируемая `startServer()` допускала запуск без pool и fallback на память даже при production-конфигурации.
- `src/server.js` и `src/store.js` содержали устаревшие комментарии, утверждавшие, что сервер целиком работает в памяти.
- Production `.env.example` содержал некорректный placeholder `DATABASE_URL`, включал memory mail transport и не задавал обязательные production-параметры.
- Конфигурация по умолчанию требовала телефон, хотя SMS-провайдер отключён и решение продукта — email-first, без SMS на первом этапе.
- `TemporaryMatrixEngine` использует Matrix Olm/Megolm. Это не целевой production-протокол: зафиксированное решение владельца — MLS (RFC 9420) для личных и групповых чатов. Нельзя считать этот временный адаптер постоянным или подключать его в production.
- В репозитории есть отдельный архивный каталог движка. Он не совпадает с POC побайтно и содержит исторические отличия; удалять его без полного tree/reference audit нельзя.

## 3. Проверка серверного хранилища

Статическая инвентаризация `storage.<method>()` в серверном API выявила 173 вызываемых имени. Все 173 имени присутствуют в PostgreSQL store и memory store. Это проверка соответствия интерфейса по именам, не доказательство корректности каждой SQL-операции и не замена интеграционным тестам.

## 4. Изменения, внесённые в этой задаче

- `src/main.js`: production-конфигурация без PostgreSQL pool теперь отклоняется до открытия порта.
- `test/main.test.js`: добавлен тест запрета production-запуска без PostgreSQL.
- `src/config.js`: телефон стал необязательным по умолчанию; обязательность включается явно через `INONE_REQUIRE_PHONE=true`.
- `test/config.test.js`: добавлены проверки email-first defaults и выключенного SMS.
- `src/server.js`, `src/store.js`: комментарии приведены в соответствие с фактической границей persistence.
- `README.md`, `DEPLOY.md`, `.env.example`: разделены серверный и криптографический движки; уточнены alpha-статус, production-параметры и ограничения.
- `mobile/DART-BACKEND-INTEGRATION.md`, `mobile/API-INTEGRATION.md`, `mobile/API-CONTRACTS-BETA-1.md`: ссылки на исходники и тесты переведены на актуальный POC-путь.

## 5. Что не подтверждено

- `npm test`, `npm run test:db`, миграции и запуск сервера в этой задаче не выполнялись.
- Нет подтверждения актуального успешного CI для новых коммитов.
- Не выполнены production backup/restore drill, нагрузочные тесты, проверка нескольких экземпляров и реальный deploy.
- Реальная SMTP-доставка с домена и SPF/DKIM/DMARC требует проверки.
- SMS-провайдер не подключён.
- OpenMLS/Rust ↔ Flutter FFI, Keychain/Keystore, защищённое локальное хранилище, фоновые/offline сценарии и физические iOS/Android тесты требуют отдельного завершения.
- Независимый аудит криптографии и сервера не подтверждён.

## 6. Политика архивации

Не удалять и не перемещать `inone-development-archive-0.6.0/engine` до полного сравнения деревьев, проверки ссылок и фиксации retention-решения. Архив не используется как актуальный backend source в мобильных документах, но содержит историческую реализацию и доказательства происхождения. Старые HTML/WebView-материалы остаются в `мусорный ящик/` согласно ранее принятой миграции.

## 7. Критерии принятия постоянного движка

1. Единственная поддерживаемая серверная точка запуска — `inone-engine-poc-0.6.0/src/main.js` (переименование каталога/версии — отдельное решение).
2. Production всегда использует PostgreSQL; запуск с memory store невозможен.
3. Все server storage operations имеют PostgreSQL implementation и покрыты тестами на PostgreSQL.
4. Миграции проходят на чистой БД и на копии предыдущей версии с сохранением данных.
5. TLS proxy, SMTP, объектное хранилище, backup/restore, мониторинг, журналы и alerting проверены в целевой среде.
6. Клиентская криптография соответствует MLS; временный Matrix/Megolm adapter не входит в production path.
7. Пройдены Android/iOS device tests, threat-model review и независимый security/crypto audit.
8. Все обязательные CI jobs зелёные на точном release SHA.

**Вывод:** серверный POC уже имеет PostgreSQL persistence path и развитую тестовую базу, но остаётся alpha-кандидатом. Криптографический компонент из `TemporaryMatrixEngine` не является утверждённым постоянным движком. Называть весь InOne engine постоянным и безопасным до выполнения критериев выше нельзя.
