## Что нельзя класть в репозиторий
- Пароли, токены, закрытые ключи, строки подключения с учётными данными.
- Секреты задаются через окружение. Пример с плейсхолдерами — `.env.example`.
- Тестовые значения (пароли тестовых аккаунтов, пепперы, секрет документов) генерируются при каждом запуске тестов.
- Проверка перед публикацией: поиск по шаблонам (ключи, токены, строки подключения, литералы паролей) должен давать ноль совпадений.

## Политика выпуска
- Каждый релиз: снимок без секретов и сборочных каталогов, отчёт о тестах, аудит зависимостей (npm audit), запись в CHANGELOG.
- Копия релиза хранится в защищённом месте только для чтения, с контрольными суммами SHA-256. Владелец получает копию с контрольной суммой.
- Каждый бета-релиз содержит обновления безопасности и, по возможности, другие обновления.

## Известные риски и открытые пункты
- Внешний аудит безопасности — во время беты (решение владельца).
- cargo audit для ядра клиента на Rust не выполнен. npm audit на alpha.37: 0 уязвимостей.
- Проверка «чистым контекстом» (отдельным проверяющим агентом) не выполнена.
- Открыты пункты беты 6.2–6.10 (глубокие ссылки, метрики, отправитель FCM и APNs, внешняя копия и ключ, квота на пользователя, сроки сессий, остатки изоляции, нагрузка 500+ участников). См. DEVELOPMENT_REGISTER.md.
- Клиентская часть шага 5.9 (выбор организации и понятные ошибки в приложении) выполняется в клиентском проекте.
