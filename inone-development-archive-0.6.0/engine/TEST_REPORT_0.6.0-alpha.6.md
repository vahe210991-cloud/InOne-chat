# Проверка inone-engine-poc 0.6.0-alpha.6 (восстановление по D1, D5 — часть 1, и D8)

Среда: контейнер, PostgreSQL 16, Node.js v22.22.2.

## Итоги

- Набор в памяти: 49 из 49 в чистой распаковке архива.
- Набор на PostgreSQL: 22 из 22 в чистой распаковке архива.
- Поломки правил: 7 из 7 пойманы своими тестами (таблица ниже).
- **Нестабильность:** в одном из 13 полных прогонов набора в памяти упал один тест, имя не записано. Воспроизвести не удалось (12 прогонов зелёные). Подозрение — тест C-04, который сравнивает медианы времени ответа, но это не подтверждено. См. раздел «Нестабильность».

## Что проверено

- Новый пароль сразу после кода; старый пароль не подходит (`восстановление: новый пароль сразу…`).
- Первый вход с нового устройства после восстановления — только по коду из письма; неверный код отклоняется (`восстановление: новый пароль сразу…`).
- Старые устройства работают 48 часов и отключаются после этого (`через 48 часов…`).
- Отмена со старого устройства возвращает прежний пароль и отключает новые устройства (`восстановление: новый пароль сразу…`).
- Отменить восстановление не может устройство, появившееся после запроса (`устройство, появившееся после запроса…`).
- PIN не снимается восстановлением; без PIN восстановление не проходит (`восстановление требует PIN…`).
- После пяти неверных кодов новые коды не выдаются на час; не больше трёх кодов в час (`после пяти неверных кодов…`, `не больше трёх кодов…`).
- Украденное устройство не читает сообщения после восстановления (`украденное устройство…`).
- На PostgreSQL: новый пароль и время создания устройства сохраняются в базе (SD16).

## Поломки: каждое правило заменялось ошибочным вариантом по одному

| Поломка | Тесты, которые её поймали |
|---|---|
| BR1: отменить может любое устройство | `устройство, появившееся после запроса…` |
| BR2: нет проверки кода при первом входе | `восстановление: новый пароль сразу…`, `устройство, появившееся…`, `украденное устройство…` |
| BR3: старые устройства отключаются сразу | `восстановление: новый пароль сразу…`, `через 48 часов…`, `устройство, появившееся…`, `восстановление требует PIN…` |
| BR4: старые устройства не отключаются через 48 часов | `через 48 часов…`, `восстановление требует PIN…` |
| BR5: восстановление снимает PIN | `восстановление требует PIN…` |
| BR6: новые коды выдаются во время блокировки и сверх лимита | `после пяти неверных кодов…`, `не больше трёх кодов…` |
| BR7: смена пароля в базе не работает | SD16 (на PostgreSQL) |

После каждой поломки файлы восстанавливались побайтово.

## Нестабильность

В прогоне набора в памяти, который шёл сразу после проверки базы и поломок, упал один тест. Журнал в тот момент показал только число провалов (48 из 49), имя не записано. Ещё шесть полных прогонов подряд и три отдельных прогона прошли. Тест C-04 сравнивает медианы времени ответа с порогом «неизвестный логин не быстрее половины времени существующего»; при нагрузке на процессор такой тест может ложно сработать. Это предположение. Действие: сделать C-04 устойчивым (больше замеров, сравнение нескольких серий) и при сбое сохранять имя теста и значения.

## Не проверено и известные ограничения

- **Состояние восстановления в памяти сервера.** Перезапуск сервера внутри 48-часового окна сотрёт отметку «отключить старые устройства», и они останутся активны. До продакшена это критично. Исправляется переносом состояния в PostgreSQL — следующий шаг М1.
- **SMS (D5) не подключён.** Восстановление держится на одном факторе — почте. Выпускать его пользователям нельзя.
- Реальная доставка писем и кодов.
- Экраны клиента для кода подтверждения и новых уведомлений.
- Очистка таблицы счётчиков входа (C-15).
