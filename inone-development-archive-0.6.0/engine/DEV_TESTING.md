# Тестирование на сервере разработки

- **Обновлено:** 2026-11-01 10:08 UTC

## Что сейчас можно проверить

- Клиента InOne ещё нет: экранов для запуска нет. Проверка идёт тестами (`npm test`) и запросами к серверу.
- Почта: письма с кодом пока не отправляются, потому что нет домена и почтового ящика. Это не из-за агрегатора: агрегатор нужен для SMS, а SMS в запуске не используется.
- Для разработки код подтверждения почты можно задать фиксированным: `INONE_DEV_EMAIL_CODE=000000`. Он работает только при `NODE_ENV=development` и не принимается в продакшене.

## Запуск сервера разработки

1. Создать базу и применить миграции:
   `DATABASE_URL=postgresql://HOST:5432/DATABASE (логин и пароль задаются переменной окружения)<пароль>@localhost:5432/inone_dev npm run migrate`
2. Запустить сервер:
   `DATABASE_URL=postgresql://HOST:5432/DATABASE (логин и пароль задаются переменной окружения)<пароль>@localhost:5432/inone_dev NODE_ENV=development INONE_DEV_EMAIL_CODE=000000 INONE_REQUIRE_PHONE=false npm start`
3. Проверить: `curl http://localhost:8080/healthz` должен ответить `{"status":"ok"}`.

## Создание аккаунта владельца

`INONE_DEV_EMAIL_CODE=000000 node scripts/dev-create-account.mjs http://localhost:8080 owner@example.test owner 'Ваш пароль'`

Инструмент проходит обычную регистрацию: почта, код, пароль, никнейм. Пароль в вывод не попадает. Аккаунт создаётся на том сервере, который запущен у вас: на сервере в песочнице его не будет.

## Вход

`curl -X POST http://localhost:8080/login -H 'content-type: application/json' -d '{"email":"owner@example.test","password":"Ваш пароль","deviceId":"laptop","label":"Тестовый ноутбук","platform":"test"}'`

Если сервер попросит подтвердить новое устройство, подтвердите его с первого устройства.
