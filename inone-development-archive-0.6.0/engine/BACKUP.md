# Резервные копии и восстановление базы (пункт 4)

- **Дата:** 2026-10-30 19:21 UTC (Ереван UTC+4).
- **Что есть:**
  - `scripts/backup-db.sh` — копия в формате custom, контрольная сумма рядом, хранение последних N копий (`BACKUP_KEEP`, по умолчанию 14).
  - `scripts/restore-db.sh` — восстанавливает только копию с совпавшей контрольной суммой и только в пустую базу. Боевую базу не трогает.
  - `scripts/verify-restore.mjs` — сверка: одинаковые таблицы, одинаковое число строк в каждой, одинаковые версии миграций. Отказывает, если исходная база не база движка.
  - `test/backup.test.js` — 3 теста на настоящей PostgreSQL. Проверено поломками: восстановление ничего не делает; контрольная сумма не проверяется; старые копии не удаляются; сверка принимает пустую базу — каждый раз падает нужный тест.
- **Замер** (база движка: 6015 строк в 37 таблицах, 14 миграций): копия 0,11 с, восстановление 0,25 с, копия 84 КБ. Объём малый: время на боевом объёме будет другим, его покажет первая учебная проверка.

## Расписание (рекомендация)
Ежедневно в 03:00 UTC:
```
0 3 * * * cd /opt/inone && DATABASE_URL=... BACKUP_DIR=/var/backups/inone BACKUP_KEEP=14 ./scripts/backup-db.sh >> /var/log/inone-backup.log 2>&1
```

## Учебная проверка (раз в неделю)
1. Создать пустую базу `inone_drill`.
2. Восстановить последнюю копию: `./scripts/restore-db.sh <файл.dump> <адрес inone_drill>`.
3. Сверить: `node scripts/verify-restore.mjs <адрес боевой базы> <адрес inone_drill>`.
4. Удалить `inone_drill`. Записать время восстановления: оно и есть RTO на боевом объёме.

## Цели
- **RPO:** 24 часа (копия раз в сутки).
- **RTO:** будет подтверждён учебной проверкой на боевом объёме.

## Что не сделано (открыто)
1. Внешнее хранение копий вне сервера — обязательно. Место (свой сервер или облако) решает владелец.
2. Шифрование копий — обязательно: в копии данные аккаунтов и хеши. Нужен ключ и место его хранения.
3. Непрерывная архивация WAL (восстановление на момент времени) — не сделано. Без неё возможна потеря до суток данных.
4. Отдельная роль для копирования с минимальными правами. В тестах используется роль приложения, которая умеет создавать базы; в эксплуатации нужна отдельная роль.
5. Копии файлов — появятся вместе с загрузкой файлов (пункт 9).
6. Мониторинг: алерт, если свежей копии нет.
