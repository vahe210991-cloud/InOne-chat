# Проверка inone-engine-poc 0.6.0-alpha.11 (лимиты регистраций, восстановления и SMS)

Среда: контейнер, PostgreSQL 16, Node.js v22.22.2.

## Итоги

- Набор в памяти: 63 из 63 (теперь включает `limits.test.js`).
- Набор на PostgreSQL: 29 из 29 (включая SD23 про перезапуск).
- Поломки BL1–BL5 пойманы тестами. После каждой поломки файлы восстанавливались и сравнивались побайтово.

## Что проверено

- Регистрации с одного адреса: третья в окне получает 429, аккаунт не создаётся; после окна регистрация снова проходит (`регистрации с одного адреса…`).
- Запросы восстановления с одного адреса: третий получает 429, в том числе по несуществующему аккаунту; отклонённый запрос не шлёт SMS; после окна снова проходит (`запросы восстановления с одного адреса…`).
- SMS на один номер: третий аккаунт на тот же номер получает 429, аккаунт не создаётся (`на один номер SMS…`).
- Счётчики регистраций переживают перезапуск сервера на базе (SD23).

## Найдено при проверке

- Новый лимит регистраций сломал тест C-04: тот регистрирует двенадцать аккаунтов с одного адреса, и на двенадцатом сервер отвечает 429. Это не время ответа, а лимит. Порог поднят только в этом файле; логика входа не менялась.
- Тест параллельной регистрации SD2 делает двадцать регистраций с одного адреса. Порог для него поднят, сама проверка гонки не менялась.
- Файл `limits.test.js` не входил в скрипт `npm test`. Исправлено; раньше набор был неполным.

## Не проверено и известные ограничения

- Адрес определяется за обратным прокси только при `trustProxy` и прокси, который перезаписывает `X-Forwarded-For`.
- Пользователи за одним NAT делят адрес. Пороги надо подобрать по реальным данным.
- Окна фиксированные: на границе окна возможен всплеск вдвое.
- Очистка строк `rate_limits` не сделана.
- Нестабильность теста C-04 как таковая не разобрана: сейчас падение объяснено лимитом.
