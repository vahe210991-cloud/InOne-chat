# Мобильный мост MLS для Flutter

- **Что здесь:** `mls-bridge` — Rust-библиотека поверх OpenMLS 0.9.2 с простым интерфейсом (личность, группа, приглашение, приветствие, сообщение, коммит), которую будет вызывать Flutter. Скрипты сборки для Android и iOS. Конвейер GitHub Actions — в `.github/workflows/mls-mobile.yml`.
- **Тесты на Linux:** `cd mls-bridge && cargo test --locked` (нужен Rust 1.91 или новее).
- **Сборка Android:** `scripts/build-android.sh` — нужны Rust с целями Android, cargo-ndk и Android NDK (`ANDROID_NDK_HOME`).
- **Сборка iOS:** `scripts/build-ios.sh` — только на macOS с Xcode.
- **Статус:** тесты на Linux проходят; сборки Android и iOS не выполнялись (в песочнице нет NDK, Flutter SDK и целей Rust для мобильных платформ). Конвейер не запускался на GitHub.
- **Следующий шаг:** Dart-мост (flutter_rust_bridge) и первый запуск конвейера в вашем репозитории.

## Ядро клиента (mls-client)

- **Что делает:** вход (первое устройство или по подтверждению с существующего), ключевые и резервный пакеты, комнаты и приглашения, сообщения, перезапуск с сохранением состояния, догон по эпохам, список участников, отзыв устройства и удаление его листа из групп, очередь сообщений без связи, повторы синхронизации с паузами, отправка с идентификатором клиента.
- **Ключ базы:** ядро получает его через интерфейс `KeyStore`. Платформа реализует его через Keychain (iOS) или Keystore (Android). `MemoryKeyStore` — только для тестов.
- **Фоновая работа:** `sync_retrying` и `flush_outbox` вызывает планировщик платформы (BGTaskScheduler на iOS, WorkManager на Android).
- **Тесты:** `cd mls-client && cargo test --locked`. Тесты поднимают настоящий сервер движка; путь к движку — переменная `INONE_ENGINE_DIR`.
- **Ограничения:** экранов и моста FRB нет (нет Flutter SDK в среде); планировщик и уведомления платформы не реализованы.
