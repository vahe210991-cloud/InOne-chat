# Проверка inone-engine-poc 0.6.0-alpha.5 (защита входа по D7)

Среда: контейнер, PostgreSQL 16.15, Node.js v22.22.2.

## Что сделано и проверено

- Жёсткая блокировка логина заменена тремя счётчиками: пара «адрес и логин», адрес, логин (см. CHANGELOG).
- На PostgreSQL: 21 из 21. Новые проверки: SD13 (блокировка адреса не закрывает вход владельцу с другого адреса), SD14 (уведомление владельцу при неудачах с разных адресов), SD15 (ограничение адреса при переборе разных логинов). SD10 переписан под задержки.
- В памяти: 46 из 46. Один тест переписан: он проверял старое правило «пять неверных паролей — блокировка даже с верным паролем». Теперь проверяется задержка после трёх неудач и возврат после минуты.

## Поломки: каждое правило заменялось ошибочным вариантом, по одному

| Поломка | Тест | Что показал тест |
|---|---|---|
| Блокировка по логину для всех адресов | SD13 | ожидалось 200, получено 429: владелец с другого адреса не вошёл |
| Уведомление владельцу не отправляется | SD14 | ожидалось true, получено false: уведомления нет |
| Нет нарастающих задержек по паре | SD10 | ожидалось 3 ответа 401, получено 30 |
| Нет ограничения адреса | SD15 | тест упал на проверке ответов после тридцатой неудачи (ожидалось 429) |

После восстановления файлов: 21 из 21 на базе, 46 из 46 в памяти.

## Не проверено

- Работа за реальным обратным прокси (X-Forwarded-For в настоящей сети).
- Очистка таблицы счётчиков и экран уведомления в клиенте.
- Нагрузка и несколько процессов сервера одновременно.
